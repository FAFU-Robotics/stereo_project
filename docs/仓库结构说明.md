# 仓库结构说明

本文档说明每个目录的职责、哪些内容不入库、以及新增文件应该放哪里。**它同时是一份“为什么这样摆”的记录**——结构不是随手长出来的，每条限制背后都有代价。

## 1. 顶层布局

```
stereo_project/
├── README.md                 项目门面：定位、快速开始、性能与精度摘要、文档导航
├── README_SDK.md             SDK 快速上手（pip 装、三行代码、约定）
├── LICENSE                   MIT（仅覆盖自有代码）
├── NOTICE.md                 许可边界：third_party 为 NVIDIA 研究许可，不可商用
│
├── main.py                   实时链路入口（preview / depth / pointcloud）
├── app_entry.py              统一 CLI + 图形菜单（--selftest / --where / --launcher / --version）
├── app_paths.py              路径解析（源码运行 vs 打包运行两套根目录）
├── camera.py                 采集：设备探测、后端回退、尺寸校验、安全释放
├── camera_guard.py           相机占用锁（output/.camera.lock 写 PID）
├── calibration.py            标定、去畸变、双目校正
├── stereo_depth.py           FFS 模型加载、预处理、推理（含 Python 3.14 的 torch.compile 补丁）
├── depth_utils.py            视差转深度、无效值、范围过滤、中文路径安全写图
├── pointcloud.py             点云生成、过滤、下采样、PLY
├── pipeline_threaded.py      三线程流水线（采集 / 推理 / 显示解耦）
├── runtime.py                新链路：显示循环 + 按键
├── viewer.py / view3d.py     旧链路显示与 Open3D 窗口
├── profiler.py / monitor.py / logger.py   分阶段计时、资源监控、日志
├── config.yaml               全部可调参数（8 段，逐条带注释与实测依据）
├── pyproject.toml            包元数据（版本动态取自 SDK_VERSION）
├── requirements.txt          依赖清单与“为什么是这些版本”
│
├── stereo_sdk/               Python SDK（对外稳定层，GUI 与外部程序只碰这一层）
│   ├── __init__.py           导出 Session / MockSession / CalibInfo / export_result
│   ├── session.py            真会话：线程、锁、参数、标定热重载
│   ├── mock.py               合成场景会话（无相机无 torch）
│   ├── types.py              FramePair / DepthResult / 参数表 / SDK_VERSION
│   ├── export.py             PLY、深度 PNG/NPY/TIFF、视差 PNG、掩码、整套导出
│   ├── calib.py              CalibInfo（只读）+ 标定文件查找顺序
│   ├── recorder.py           Recorder：按会话目录落盘（ASCII PLY）
│   └── py.typed              类型标记
│
├── tools/                    命令行工具、标定 GUI、主界面（viewer_shell.py）、启动器
├── examples/                 六个可直接运行的 SDK 示例
├── tests/                    离线自检（假相机 + 假模型）与冒烟测试
├── docs/                     全部文档（见 docs/README.md）
├── packaging/                PyInstaller 配置、构建脚本、打包测试报告
├── third_party/              Fast-FoundationStereo 官方源码（勿改）
│
├── calibration/              标定结果（stereo_calib*.yaml），入库
├── weights/                  模型权重（68 MB），已从 git 索引移除（文件仍在本地）
├── output/                   运行输出：快照、数据集、基准 JSON，**不入库**
├── logs/                     运行日志，**不入库**
└── release/                  EXE 交付物（5.0 GB / 15761 文件），**不入库**
```

## 2. 目录职责与边界

| 目录 | 职责 | 不要放进这里 |
|---|---|---|
| `stereo_sdk/` | 对外稳定接口。内部怎么重构，只要这层 API 不变，调用方就不用改 | 相机驱动、GUI 代码、任何 `import torch` 的顶层语句 |
| `tools/` | 一次性或反复使用的运维脚本、标定 GUI、启动器 `.bat` | 被 `main.py` 或 SDK 依赖的模块（那些必须在根目录） |
| `examples/` | 教学用、可独立运行、必须支持 `--mock` | 生产逻辑。示例被复制走也要能跑，所以只依赖公开 API |
| `tests/` | 离线自检，不需要相机与显卡 | 需要硬件的集成测试（会让人无法在 CI 里跑） |
| `docs/` | 面向使用者的说明与实测记录 | 代码生成物、截图以外的大文件 |
| `packaging/` | 打包配置与打包测试报告 | 打包产物（`release/` 与 `build/` 已忽略） |
| `third_party/` | 上游源码，保持官方目录结构 | **任何本地改动**——改了就再也无法与上游 diff |
| `calibration/` | 标定结果 YAML，**入库**（小且决定数据是否可信） | 采集的标定图片（在 `output/`） |

## 3. 为什么源码模块必须留在根目录

`stereo_sdk/session.py` 里 `from camera import ...`、`from pipeline_threaded import ...` 这类导入，依赖的是**仓库根目录在 `sys.path` 上**这一前提。`pyproject.toml` 的 `py-modules` 段把同一批模块平铺安装进 site-packages，从而让 `pip install -e .` 之后行为一致。

如果把 `camera.py` 挪进 `src/` 或 `stereo_sdk/`，需要同时改：`pyproject.toml` 的 `py-modules`、所有 `import` 语句、`app_paths.py` 的根目录推导、`packaging/StereoCamera.spec` 的 `pathex`、以及五处 `.bat` 里的相对路径。这类重排的收益（目录更好看）远小于风险（打包与启动器全线失效），因此本项目**刻意保持扁平布局**。

> 结论：新增模块请放在根目录（若被 SDK 或 `main.py` 依赖），或放 `tools/`（若只是独立脚本）。

## 4. 什么不入库，为什么

| 路径 | 体积 | 不入库的原因 | 怎么重新获得 |
|---|---|---|---|
| `release/` | 5.0 GB | GitHub 单资产上限 2 GB；clone 会被拖成 5 GB | `packaging/build_exe.ps1` 重建 |
| `weights/*.pth` | 68 MB | 上游研究版权重，且体积超建议值；已 `git rm --cached`，历史提交仍含该文件 | `python tools/fetch_ffs_weights.py` |
| `output/` | 252 MB | 运行产物，随时可重建 | 跑一次程序 |
| `logs/` | 12 KB | 日志含本机路径 | 跑一次程序 |
| `_work/` | 350 MB | 隔离测试用的临时安装目录（如 OpenCV 4.x、下载的 wheel） | 按需重建 |
| `.venv-build/` | — | 打包用虚拟环境 | `build_exe.ps1` 会重建 |
| `__pycache__/` | 796 KB | 字节码 | Python 自动生成 |
| `third_party/**/assets/` | 33 MB | 上游演示图片/视频，与功能无关 | 用上游原始 zip 解压 |
| `RenderOption_*.json` | — | Open3D 保存视图设置时写出的文件，每次运行都可能改名 | 自动生成 |

`.gitignore` 按上述规则分组，每组都有注释说明“为什么排除”。**新增忽略规则请写在对应分组里**，不要堆到文件末尾。

## 5. 新增文件放哪里（决策表）

| 你要加的东西 | 放这里 | 附加要求 |
|---|---|---|
| 一个新的运维/诊断脚本 | `tools/` | 在 `tools/README.md` 登记一行 |
| 一个给使用者的示例 | `examples/` | 必须支持 `--mock`，并在 `examples/README.md` 登记 |
| 一个被 SDK 依赖的模块 | 仓库根目录 | 同步加进 `pyproject.toml` 的 `py-modules` |
| 一份使用说明 | `docs/` | 在 `docs/README.md` 的索引表里登记 |
| 一次实测记录 | `docs/` | 文件名带日期或阶段号，并写明测试环境 |
| 打包相关 | `packaging/` | 产物一律落到 `release/`（已忽略） |
| 上游代码 | `third_party/` | 保持官方结构，不改一行 |

## 6. 命名约定

| 类型 | 规则 | 例子 |
|---|---|---|
| Python 模块 | 小写下划线 | `camera_guard.py` |
| 启动器 `.bat` | 中文名（面向用户，双击识别度高） | `启动_普通权限.bat` |
| 文档 | 中文名，按主题而非日期 | `标定GUI使用说明.md` |
| 实测记录 | 阶段号或日期前缀 | `阶段5_标定实测记录.md` |
| 输出目录 | 时间戳_毫秒_标签 | `20261028_171235_486_cloud` |

`.bat` 文件内容**必须保持 ASCII**：`cmd.exe` 按当前 OEM 代码页逐字节解析批处理文件，文件里出现非 ASCII 字符会导致解析错位。因此启动器里只写英文提示，中文一律走 Python 打印。

## 7. 版本号只有一个来源

`stereo_sdk/types.py` 的 `SDK_VERSION` 是唯一来源：

- `pyproject.toml` 用 `dynamic = ["version"]` 从它读；
- `app_entry.py --version` 读同一处；
- 发版时改这一行即可，不要在别处再写版本号。
