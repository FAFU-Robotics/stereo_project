# 标定工作台（GUI）使用说明

> 适用版本：`tools/calib_gui.py`（新增，未修改任何原有脚本的行为）
> 必需依赖：Python 3.10+（含 tkinter）、opencv-python、numpy、pyyaml
> 界面代码：`tools/calib_gui.py`（业务）+ `tools/gui_theme.py`（配色与控件样式）
> 选装依赖：pillow（装了就快一点，不装也能用——自动退回 Tk 自带的 PNG 解码）

## 1. 它解决什么问题

原先"采集 → 标定 → 检查 → 保存"要跨三个命令行脚本与一个 .bat 菜单，中间还要人记住时间戳目录。
现在合成一个窗口四页，每页只回答一个问题：

| 页 | 回答的问题 | 失败时会发生什么 |
|---|---|---|
| ① 采集 | 这一帧够格保存吗 | 不达标时按钮无效并给出原因，不会存下废帧 |
| ② 标定 | 这批图能算出可用的参数吗 | 后台线程计算，界面不冻结；帧数不足会直接告诉你差多少 |
| ③ 检查 | 校正后左右图的同一物点在同一行吗 | 给数字（分区 |dy|）也给画面（叠放 + 水平线） |
| ④ 保存 | 这次结果比上次好还是差 | 自动归档旧文件，可对比、可回退 |

## 2. 启动

```
双击 tools\calib_gui.bat
或
python tools\calib_gui.py
```

`.bat` 会按「`PY=` 行 → 常见安装路径 → PATH 上的 python」的顺序找一个解释器，然后逐个导入
`tkinter`/`cv2`/`numpy`/`yaml` 检查；缺哪个就打印该装什么，不会直接闪退。
pillow 只做提示不拦截——缺它时界面照常可用。

**找不到解释器时**：`calib_gui.bat` 自己内置了三级探测（① `set "PY=..."` 那一行 ② 常见的用户级安装路径 ③ `where python`）。三级都不对时，直接改文件顶部 `set "PY=..."` 那一行。
**已验证可用的版本**是 Python 3.14.6（独立安装）。用 `where python` 确认你实际用的是哪一个。

**高分屏**：`calib_gui.py` 在创建窗口前声明了 Per-Monitor DPI 感知（`SetProcessDpiAwareness(2)`），
并按实测缩放调整 `tk scaling`。不做这一步，Windows 会把 125%/150% 下的界面按位图拉伸，
文字发虚——本机实测缩放为 **1.50×**，属于明显会糊的那一档。

## 3. 界面与快捷键

### 3.1 窗口结构

窗口自上而下固定四层，每层职责单一，不需要记按钮在哪：

| 区域 | 内容 | 为什么放在这里 |
|---|---|---|
| 顶栏 | 标题、四步流程提示、依赖版本（cv2 / numpy / 显示通道） | 版本放窗口上而不是藏进"关于"：装了两个 OpenCV 导致结果不一致，是这类项目最常见的求助原因 |
| 页签 | ① 采集 / ② 标定 / ③ 检查校正效果 / ④ 保存参数 | 顺序即操作顺序 |
| 页体 | 左侧主工作区 + 右侧参数卡片 | 卡片比窗口底色浅一档并带 1px 描边，把"参数"与"结果"在视觉上分开 |
| 底栏 | 采集进度胶囊 + 状态文字 + 相机状态 | 胶囊颜色本身就是结论，不必读文字 |

### 3.2 配色约定（彩色只用于表达质量）

| 颜色 | 含义 |
|---|---|
| 蓝 `#2f81f7` | 主操作，该点的那一个按钮 |
| 绿 `#3fb950` | 达标、已载入 |
| 暖黄 `#d29922` | 还差一步，不是错误 |
| 红 `#f85149` | 失败、删除类操作 |

其余部分一律深灰三档：窗口 `#0d1117`、面板 `#161b22`、卡片 `#12171e`。
这样做的目的是让"哪个是主要动作、哪个是提醒"在余光里就能分辨，而不是满屏彩块。

配色、字体、控件样式全部集中在 `tools/gui_theme.py` 一个文件里。
改一处即全局生效，不需要在四个页面里找散落的颜色字符串。
该文件用的是 ttk 的 `clam` 主题：Windows 默认的 vista 主题由系统绘制，
给按钮设 `background` 会被直接忽略，只有 clam 的颜色字段真正生效。

### 3.3 快捷键（只在第①页生效）

| 键 | 动作 |
|---|---|
| `空格` | 保存当前帧（先过质量门） |
| `F` | 强制保存（跳过质量门，用于补特殊姿态） |
| `U` | 撤销最近一帧 |
| `Delete` | 在缩略图窗里删除选中帧（连磁盘文件） |

焦点处在输入框（备注、阈值、目录）里时，这些单键不生效。
不设这道闸的话，在备注里打一个 `f` 就会存下一帧。

### 3.4 切页会自动刷新

| 切到 | 自动刷新 |
|---|---|
| ① 采集 | 采集清单与底栏进度 |
| ② 标定 | 采集目录下拉列表 |
| ③ 检查 | 引导条结论（是否已有标定、基线、RMS） |
| ④ 保存 | 归档历史 |

这样在文件管理器里手工删了帧、或换了一份标定文件，切一次页就能看到最新状态，不必重启程序。

## 4. ① 采集页

- **打开相机**：默认按 `config.yaml` 的 `camera` 段打开；首次约 2~5 秒。
- **保存这一帧（空格）**：四道质检门全过才保存。门的数值在右侧可现场改，改完立即生效。
- **强制保存**：跳过质检门，用于"这一帧角度难得、但对比度稍低"的情况；报告里会标记 `[强制]`。
- **撤销上一帧**：撤掉最后一张并删除它的两个文件。
- **删除指定帧…**：弹出帧列表（含姿态与角点数），选中任意一帧删除；支持 Delete 键与双击。
  用于"第 5 张糊了"这种中途发现的情况——撤销只能退最后一帧，退不到中间。
- **覆盖热力图**：看角点落在画面的哪些格子里。**这是判断标定可信度最直接的一张图**——
  只在中央一块有颜色，说明边缘畸变没有任何实测约束。
- **帧缩略图…**：把已保存的每一帧摆成 4 列网格。单击选中、双击看大图、Delete 删除。
  为什么需要它：角点数都是 48 的两帧，可能一帧板子在中央、一帧贴边被裁——数字一样，价值完全不同。
  没有采集会话时也能用：会读当前选的采集目录，此时是只读（不能删）。
- **完成采集 → 去标定**：写 `capture_report.txt` / `.json` 并跳到第二页。

**底栏左侧常驻一格"还差多少"**，颜色就是判断依据：

| 颜色 | 含义 |
|---|---|
| 深黄 | 数量还不够，继续拍（同时列出还差几对、缺几类姿态） |
| 深灰 | 数量够了但姿态清单没齐（比如一个左倾都没有） |
| 深绿 | 数量与姿态都达标，可以去做标定了 |

右侧"采集清单"下面还会给出**下一步动作**（例如"把板子移到画面左上""板子向左倾 20° 以上"），
不是只报数——报数解决不了"我该拍什么"。

质检门沿用 `capture_calib.py` 的三项判据（每格像素、清晰度、最差区域对比度），
GUI 没有另立标准，所以命令行与界面永远一致。

## 5. ② 标定页

选目录 → 填板子参数 → 开始标定。结果是 `calibration.py` 的原始输出，外加一张**体检表**。

体检表除 RMS 之外还查这些（这些是 RMS 抓不到的）：

| 项目 | 不合格说明什么 |
|---|---|
| 基线量级 | 米/毫米混用，或 `square_mm` 填错一个数量级 |
| T 方向 | 左右眼顺序反了（`config.camera.split`） |
| 图像尺寸一致性 | 换了分辨率却用旧标定，深度会整体错倍数 |
| 畸变系数量级 | 鱼眼视场配针孔模型时边缘发散 |
| **校正缩放比** | `P1.fx / K1.fx` 明显大于 1：畸变在四周失稳，画面被放大裁切 |
| 校正后极线失准 | 行没对齐，或校正后角点已经检不到 |

**校正缩放比这一条值得单独说**：实测中它抓到过 `P1.fx / K1.fx = 4.1` 的情况——
RMS 只有 0.25 px 看着很漂亮，但 `stereoRectify` 把画面放大了四倍，板子直接被裁出视野，
校正后一帧角点都检不到。根因是标定板只覆盖了画面中央，边缘畸变没有约束。
RMS 无法反映这件事，缩放比可以。

**「取消」按钮**（③页生成检查图时同样可用）——它能停在哪、不能停在哪，必须说清：

| 阶段 | 能否立即停 | 原因 |
|---|---|---|
| 读取角点 | 能，下一帧之前 | 逐帧循环，有检查点 |
| 主计算（各眼内参 + `stereoCalibrate`） | **不能**，要等它算完 | OpenCV 是一次不可分割的原生调用，没有回调钩子 |
| 校正验证 / 分区统计 | 能，逐帧检查 | 同样是循环 |

所以点取消后的真实表现是：状态行显示"正在取消…（主计算需等它算完，通常 1~3 秒）"，
然后日志出现 `[取消] 用户中止，本次结果未采用`，按钮复位，**不写任何文件、不留下半份结果**。
如果你的帧多、主计算要十几秒，那就得等这十几秒；这不是卡死。

## 6. ③ 检查页

顶部有一条**引导条**，按当前状态给出下一步：

| 状态 | 引导条说什么 | 可用按钮 |
|---|---|---|
| 本次刚标定完 | 显示基线 / rect fx / RMS | 都置灰（已在用） |
| 磁盘上有 `stereo_calib.yaml` 但没载入 | 提示可直接载入 | 「载入已有标定文件」可用 |
| 完全没有标定文件 | 提示先去第②页 | 只有「去第②页标定」 |

「载入已有标定文件」是为了一件事：**只想看上次的校正效果，不想重标一遍**。
它会读 `calibration/stereo_calib.yaml` 并直接生成检查图，全程不动参数。

七种显示方式，各自证明不同的事：

| 方式 | 怎么看 |
|---|---|
| 上下叠放 + 水平线 | 同一物点在两幅图里是否压在**同一条线**上（最接近人眼判据） |
| 并排 + 参考线 | 同一条线贯穿左右，适合看视差随距离的变化 |
| 红青立体 | 戴红青眼镜看深度是否连续、有无翻转 |
| 左右差值 | 对齐良好时棋盘边缘是细双线；错位会变成粗带 |
| 棋盘混合 | 左右块交替拼接，错位处出现断裂 |
| 覆盖热力图 | 角点采样的空间分布 |
| 分区 |dy| 热力图 | 3x4 分区，每格标均值与样本数 |

底部文字给出 **边缘 / 中心** 的比值。比值明显大于 1，说明畸变模型在四周吃紧——
这正是"全图平均 |dy| 很好看、但边缘实际不准"的典型形态。

`alpha` 滑块改变 `stereoRectify` 的裁切策略，只影响本页预览，不会改动已保存的参数。
旁边的 `alpha` 报告会给出每种取值的**实测有效像素比例**（用实际重采样统计，不是估算）。

## 7. ④ 保存页

- **保存并归档**：保存前若目标是当前生效文件，会先自动备份一份旧文件。
- **归档历史**：每次保存都会在 `calibration/archive/` 留一份带时间戳的副本，并写 `manifest.json`。
- **激活选中**：把某份历史设为当前生效。激活前会再备份当前那份，所以任何一次激活都能退回。
- **与上一份对比**：逐项列出基线、fx、RMS、光轴夹角的变化；基线变化超过 2% 会额外提示。
- **校验当前文件**：查必需键、矩阵形状、T 的单位量级（米/毫米混用会被抓出来）。

## 8. 与 SDK 的衔接

保存并激活新标定后，正在运行的程序**不会自动换参数**。两种做法：

```python
# 方式一：热重载（新增方法，不重启相机、不重载模型，几十毫秒）
info = session.reload_calibration()
print(info["baseline_m"], info["rect_fx"], info["rms_stereo_px"])

# 方式二：重启 Session（3~10 秒，会重新加载 FFS 权重）
```

`reload_calibration()` 会先校验标定文件的图像尺寸与相机实际分辨率是否一致，
不一致直接抛异常且**保持原参数不变**，不会出现"用了一半新参数"的中间状态。

## 9. 界面记忆（关掉再打开还是原样）

窗口尺寸与位置、当前停留的页、上次用的采集目录、四道质检门的数值、标定板参数、
③页的显示方式与 alpha —— 全部记在：

```text
output/gui_state.json      # 该目录已在 .gitignore 里，不会进仓库
```

- **首次运行**没有这个文件，各项取自 `config.yaml`（所以你的板子参数不会被默认值覆盖）。
- 之后每次关闭自动写入，下次启动原样恢复。
- 文件被写坏或手改错**不会影响启动**：读取时逐项校验，非数字回落默认、超范围夹紧到边界、
  页签越界回到第 1 页；写坏一个字段只丢那一个字段的记性。
- 想强制回到默认布局，删掉这个文件即可。也可以设环境变量 `STEREO_GUI_STATE` 指到别处，
  便于同时维护"小屏演示"和"大屏调试"两套布局。

## 10. 不开界面也能做同样的事

| 目的 | 命令 |
|---|---|
| 列出采集目录 | `python tools\calib_core.py --list` |
| 标定并打印体检表 | `python tools\calib_core.py --dir output\calib\<时间戳>` |
| 生成检查图与分区统计 | `python tools\calib_check.py --dir output\calib\<时间戳>` |
| 归档当前标定 | `python tools\calib_manage.py archive --note "说明"` |
| 列出 / 激活归档 | `python tools\calib_manage.py list` / `activate 2` |
| 对比两份标定 | `python tools\calib_manage.py diff <A> <B>` |

## 11. 已知限制（必须知道）

1. **模型仍是针孔 + 五系数畸变**，不是鱼眼模型。这颗相机标称 177.8° 视场，
   若要让画面边缘也准，标定时必须让板子覆盖到四角，否则边缘参数无约束。
2. **纸基标定板不可靠**。项目实测：A4 打印 ChArUco（7x9 / 26 mm）重标后，
   校正后极线失准 12.8 px 并出现负视差；同尺寸玻璃板只有 0.07 px。
   要用纸板，先整面贴到亚克力或玻璃上压平。
3. **GUI 未在本机实机运行验证**：本机 Python 缺 tkinter，只做了语法编译、
   静态字段检查与无界面全链路验证（合成数据 fx 误差 0.03%、基线 0.24%、
   校正后 |dy| 0.096 px）。界面部分需要你在装有 tkinter 的机器上首次试跑。
