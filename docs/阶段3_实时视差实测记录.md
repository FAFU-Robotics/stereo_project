## 2. 结果分析

| 指标 | 实测 | 结论 |
|---|---|---|
| 端到端帧率 | **4.81 FPS** | 全分辨率（scale 1.0）下的真实速度 |
| 推理耗时 | **157.5 ms** | 与阶段 2 基准（640×480 → 156.3 ms）**吻合到 1 ms**，交叉验证成功 |
| 采集帧率 | 5.12 FPS | **被推理拖住**，不等于相机上限（裸采集实测 51.6 FPS） |
| 丢弃帧 | 1 | 说明"只取最新帧、不排队"的设计有效，**无积压** |
| 异常帧 | 0/0/0 | 采集侧稳定 |
| 预热 | 1861 → 149 → 152 ms | "用真实尺寸预热"的设计被验证有效，冷启动未污染统计 |

**瓶颈定位明确**：`采集 5.12 FPS ≈ 推理 6.4 FPS ≪ 相机能力 51.6 FPS`
→ 优化要花在**推理侧**（阶段 7：解耦线程 + TensorRT / 半精度 / 降分辨率）。

## 5. 已知待改进（阶段 7）

1. **采集与推理解耦**：当前单线程串行，采集被推理阻塞（5.12 FPS）。
   计划：采集线程 + 最新帧槽位，推理在独立线程/进程，显示取最新结果。
2. **推理加速**：当前 `build_volume=pytorch1` 且禁用 `torch.compile`（Windows 无 Triton）。
   候选：TensorRT（官方有现成脚本）、`triton-windows`、半精度、进一步降分辨率。
3. 官方 `core/geometry.py` 里的 `torch.cuda.amp.autocast` 弃用警告（不改官方代码，仅记录）。
