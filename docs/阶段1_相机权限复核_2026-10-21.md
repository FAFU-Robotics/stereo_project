# 阶段 1 相机权限复核（2026-10-21）—— 普通用户权限已经可用，不需要管理员

> 结论先行：**普通用户（Medium 完整性）可以正常打开 DECXIN 双目相机（索引 1 / DSHOW / 1280×480）。**
> 旧文档「必须以管理员权限运行」是把「低完整性 / 沙箱 / 受限会话」误写成了「普通权限」。
> 本次用项目自己的 `camera.py` 和 `main.py` 在 Medium 令牌下实测，证据如下。

---

## 1. 为什么之前会得出「必须管理员」的结论

旧文档（[阶段1_相机根因分析.md](阶段1_相机根因分析.md) 第 12 节）的核心证据是：

- 普通权限进程在 DirectShow `BindToObject` 这一步得到 `HRESULT=0x80070005 (E_ACCESSDENIED)`；
- 管理员权限进程同一步成功，并能取到 1280×480 真实画面。

本次复核发现：**当时被测试的「普通权限」进程实际是低完整性（Low）进程**，
例如在沙箱 / 受控终端 / DSH 会话里启动的 Python。**Low 完整性才是被 Windows 拒绝的原因**，
不是「非管理员」这个身份本身。真正的普通用户进程是 **Medium** 完整性。

另一个关键误判来自用户提供的一条测试结果：

```
相机索引 2 + cv2.CAP_DSHOW，普通权限下 isOpened() 和 read() 都返回 True
```

这条结果本身没错，但**索引 2 是 HP 的软件虚拟摄像头**（`OMEN Cam & Voice`），
它确实能 `isOpened()=True`、`read()=True`，但返回的是 **640×480 全黑帧**。
它只能证明「虚拟摄像头能打开」，**不能证明双目相机可用**。
项目实际使用的是索引 1（`USB Camera`，`VID_0BDA&PID_5883` = DECXIN）。

### 3.5 资源释放 / 重复打开 / dual 失败

`_work/dual_leak_test.py`（Medium）：

- `side_by_side idx=1` 连续打开→读 5 帧→`close()` 两轮，均成功；`close()` 后 `_caps = []`；
- `dual left=0, right=9`：左侧打开成功、右侧失败 → `open()` 抛 `CameraError`，
  **`_caps = []`（左侧已被释放）**，`_opened=False`；
- 失败后重新打开索引 0（640×480）成功，证明失败路径没有残留占用；
- `close()` 可重复调用（幂等）。

### 3.6 MSMF 与索引 2

- `CAP_MSMF` 对索引 0/1/2 在 Low 和 Medium 下都 `isOpened=False`；
  这不是权限问题，是本机 OpenCV/MSMF 按索引枚举的兼容性问题。
- `CAP_DSHOW` 才是本机可用后端（配置已保持 `backend: dshow`）。
- 索引 2 的 `isOpened()/read()` 成功是**虚拟摄像头的黑帧**，不能作为验收依据。

### 3.7 误把 4:3 单幅图当双目拼接会被拒绝

实测：把请求尺寸改成 `640x480` 时，MSMF 确实能返回 640×480，但它是 **4:3 单幅图**；
如果继续对半切，会得到两幅 320×480 的窄图，视差/点云全部错位。

新增 `camera.min_aspect_ratio`（默认 2.0）：`1280x480` 的宽高比 2.67 通过；
`640x480` 的 1.33 会直接报错并释放设备，不再静默继续。若确实使用其它布局的拼接相机，
把该值调小或设为 0。

## 4. 根因结论

1. **不是「普通用户 vs 管理员」**：普通用户（Medium）可以打开物理相机；
   真正被拒绝的是 **Low 完整性 / 沙箱 / 受限会话**。
2. **旧代码把任何打开失败都硬编码成「E_ACCESSDENIED，必须管理员」**，
   没有读取真实失败信息。这会把「索引错 / 被占用 / 格式不支持 / MSMF 不兼容」
   全部误报成权限问题，并让管理员启动器看起来「有效」。
3. **用户的索引 2 测试是虚拟摄像头**：`isOpened()/read()` 为 True 但画面全黑，
   不能证明双目相机可用；实际项目用的是索引 1。
4. **索引 1 本身是对的**，但固定索引会因拔插/设备顺序变化而失效；
   代码已加入可选的 `auto_detect` 与尺寸校验，默认仍保留索引 1。

## 6. 普通权限验证步骤（请按顺序做）

1. **确认是普通窗口**（不是管理员，也不是沙箱终端）：
   ```bat
   whoami /groups | findstr S-1-16
   ```
   期望看到 `Medium Mandatory Level ... S-1-16-8192`。
   若是 `Low ... S-1-16-4096`，说明当前终端是受限会话，换一个普通桌面 PowerShell。

2. **双击** `tools\启动_普通权限.bat`，菜单输入 `1`。
   期望启动日志包含：
   ```
   [相机] 索引 1（single）: dshow / 打开时传参: 已打开，首帧 1280x480
   [相机] 实际输出 1280x480，单眼 640x480，左眼 mean=...
   已打开   : mode=side_by_side idx=1 backend=dshow full=1280x480
   单眼尺寸 : 640x480   原始输出: 1280x480
   ```
   窗口应显示左右两幅真实画面，底部 `read_fail: 0`、`blank: 0`。

3. **左右不接错/不重复**：用手指遮住左镜头，应只有左画面变暗；
   遮右镜头则只有右画面变暗。两幅图不应完全相同。

4. **深度/点云仍可用**：回到菜单选 `2`（实时视差）和 `3`（实时点云），
   确认能看到视差伪彩 / Open3D 点云窗口。若只想快速回归，先跑：
   ```bat
   python tools\offline_selftest.py
   ```
   （假相机、不需要真实权重，验证深度/点云/可视化管线没被本次修改破坏。）

5. **退出释放**：在预览/视差/点云窗口按 `q` 或 `ESC`，回到菜单后再选 `1`，
   应能再次打开（说明 `release()` 正常）；同时确认没有残留 `python.exe` 占用相机。

6. **相机自检**：菜单选 `4`，或双击 `tools\相机OpenCV自检.bat --quick`。
   期望索引 1 显示「✅ 拿到真实画面 1280x480 ...」；
   索引 2 若显示「⚠️ 能打开但全是黑屏」是正常的（它是 HP 虚拟摄像头）。

7. **仍失败时**（不要直接改用管理员，先收集日志）：
   ```bat
   whoami /groups | findstr S-1-16
   python main.py --list > normal_camera_list.txt 2>&1
   python tools\probe_cameras.py --index 1 > normal_probe_idx1.txt 2>&1
   python tools\opencv_camera_check.py > normal_check.txt 2>&1
   ```
   把这三个文件 + 启动日志发出来；重点看：
   - 完整性是不是 Medium；
   - 索引 1 是否仍对应 `USB Camera`（`0BDA:5883`）；
   - 实际输出尺寸是否 1280×480；
   - 是否被别的程序占用（相机 App / 会议软件 / 另一个 python.exe）。
