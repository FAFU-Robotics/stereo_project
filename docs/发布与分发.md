# 发布与分发

本文档说明如何把 `packaging/` 的构建产物变成一个可对外下载的 Release。

## 1. 为什么不把 EXE 放进 Git

实测数据（`packaging/打包测试报告.md`）：

| 指标 | 值 |
|---|---|
| 产物体积 | 约 **5.0 GB** |
| 文件数 | **15761** |
| 其中 torch CUDA 运行库 | 约 4.3 GB |
| 单个 exe | 53 MB |

GitHub 的限制是**每个 Release 资产 2 GB**、单次 push 建议 < 100 MB、仓库建议 < 1 GB。把 `release/` 提交进仓库会让 clone 变成一次 5 GB 下载，且大概率在 push 阶段失败。因此：

- `release/` 已在 `.gitignore` 中排除；
- 交付物走 **7-Zip 分卷 + GitHub Releases**；
- 源码仓库保持轻量：不含权重与产物时约 68 MB，其中 38 MB 是 third_party 源码。
- 权重文件已从 git 索引移除（`git rm --cached`），但**历史提交里仍有**；首次公开前需按第 6 节处理历史，否则 clone 仍会拉下 68 MB 且违反上游研究许可。

## 2. 构建 EXE

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File packaging\build_exe.ps1
```

产物落在 `release\StereoCamera\`（PyInstaller onedir 模式，无控制台，关闭 UPX）。构建细节与体积账见 [打包成EXE_准备清单.md](打包成EXE_准备清单.md)。

**构建前请清掉运行数据**，否则会把日志和个人路径一起发出去：

```powershell
Remove-Item -Recurse -Force release\StereoCamera\logs, release\StereoCamera\output -ErrorAction SilentlyContinue
```

## 3. 打成分卷

用 7-Zip 命令行（`-v` 指定分卷大小，单位可用 m/g）。分卷大小取 **1700m**，保证每卷都低于 GitHub 的 2 GB 单资产上限：

```powershell
cd release
& "C:\Program Files\7-Zip\7z.exe" a -v1700m -mx1 StereoCamera-v0.3.0.7z .\StereoCamera\
```

产物（实测本机 7-Zip 25.01，分卷命名为 `.7z.001`、`.7z.002`…）：

```
StereoCamera-v0.3.0.7z.001
StereoCamera-v0.3.0.7z.002
StereoCamera-v0.3.0.7z.003
```

参数说明：

| 参数 | 取值 | 理由 |
|---|---|---|
| `-v1700m` | 1700 MB/卷 | 低于 2 GB 上限并留出余量 |
| `-mx1` | 快速压缩 | 4.3 GB 是 DLL，压缩比本就有限；`-mx0` 完全不压也可，`-mx9` 会耗时很久且收益很小 |

## 4. 生成校验文件

下载端需要能验证完整性（分卷漏一卷就解压失败，但报错信息不直观）：

```powershell
cd release
Get-ChildItem StereoCamera-v0.3.0.7z.* | Get-FileHash -Algorithm SHA256 |
  ForEach-Object { "$($_.Hash.ToLower())  $($_.Path | Split-Path -Leaf)" } |
  Out-File -Encoding ascii SHA256SUMS.txt
Get-Content SHA256SUMS.txt
```

`SHA256SUMS.txt` 与三个分卷一起上传。

## 5. 上传

**方式一：网页**。仓库 → Releases → Draft a new release → 填 tag（如 `v0.3.0`）→ 拖入 4 个文件（3 个分卷 + `SHA256SUMS.txt`）→ Publish。

**方式二：GitHub CLI**

```bat
gh release create v0.3.0 release\StereoCamera-v0.3.0.7z.001 release\StereoCamera-v0.3.0.7z.002 release\StereoCamera-v0.3.0.7z.003 release\SHA256SUMS.txt --title "v0.3.0" --notes-file docs\发布说明模板.md
```

## 6. 发布说明必须写清的四件事

Release notes 不是广告。以下四条如果不写，用户会在下载 5 GB 之后才发现用不了：

1. **许可限制**：内置的 Fast-FoundationStereo 权重为 NVIDIA 研究许可，**仅限研究/评估，不可商用**（依据见 [NOTICE.md](../NOTICE.md)）。
2. **硬件前提**：需要 NVIDIA 显卡 + 支持 CUDA 12.8 的驱动；无显卡时只有预览与标定可用。
3. **未验证项**：干净 Windows 机器未验证、标定 GUI 四页未逐项人工点测（见 [../packaging/打包测试报告.md](../packaging/打包测试报告.md)）。
4. **解压方式**：必须三个分卷齐全后用 7-Zip 解第一卷，且**不能只拷 exe**。

## 7. 备选分发方式

| 方式 | 适用 | 代价 |
|---|---|---|
| 只发 `StereoCamera.exe` + `build_exe.ps1` | 用户有 Python 环境 | 用户需自行装 torch 并打包，门槛高 |
| 网盘（阿里云盘 / 蓝奏云等） | 国内用户下载速度快 | 需要维护外链，无法用 GitHub 的版本管理 |
| Git LFS | 团队内部 | LFS 按流量计费，5 GB 体积对使用者不友好 |
| 只发源码，不发二进制 | 只面向开发者 | “开箱即用”这条承诺无法兑现 |

## 8. 版本命名约定

| 内容 | 规则 | 例子 |
|---|---|---|
| Git tag | `v<主>.<次>.<修订>` | `v0.3.0` |
| EXE 分卷 | `StereoCamera-v<版本>.7z.NNN` | `StereoCamera-v0.3.0.7z.001` |
| 代码内版本号 | 唯一来源是 `stereo_sdk/types.py` 的 `SDK_VERSION` | `0.3.0` |

`pyproject.toml` 用 `dynamic = ["version"]` 从 `SDK_VERSION` 读取，`app_entry.py --version` 也读同一处。因此**改版本号只改一个地方**，不要在 `pyproject.toml` 里再写一遍。
