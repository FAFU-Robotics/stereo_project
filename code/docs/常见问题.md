# 常见问题

按“你看到的现象”查。每条都给出可验证的原因与处理办法，未经验证的猜测不写入本文件。

---

## 1. 推理相关

### 报 `no kernel image is available for execution on the device`

**原因**：装的 PyTorch 轮子不含你显卡的计算能力内核。RTX 50 系是 **sm_120**（Blackwell），cu124 及更早的预编译轮子里没有它。

**确认**：

```bat
python -c "import torch; print(torch.__version__, torch.cuda.get_device_capability(0), torch.cuda.get_arch_list())"
```

若 `get_arch_list()` 里没有 `sm_120`，就是这个问题。

**处理**：重装 cu128 及以上轮子。

```bat
python -m pip uninstall -y torch torchvision
python -m pip install torch==2.9.1 torchvision==0.24.1 --index-url https://download.pytorch.org/whl/cu128
```

### `torch.cuda.is_available()` 是 False

按顺序排查：驱动是否支持 CUDA 12.8（`nvidia-smi` 右上角的 CUDA Version）、是否装了 CPU 版 torch（版本号后面没有 `+cu128`）、是否有第二个 Python 解释器覆盖了路径。

### 报 `torch.compile is not supported on Python 3.14+`

**原因**：Python 3.14 上 `torch.compile` 是硬错误，而 FFS 的 `core/submodule.py` 用了 `@torch.compile` 装饰器，装饰器在 import 阶段就会求值。

**现状**：`stereo_depth.py` 已在 `import torch` 之后把 `torch.compile` 替换为恒等装饰器（语义等价），并用 `TORCHDYNAMO_DISABLE=1` 关闭 dynamo。**不要删除那段代码。**

**例外**：若你自己写的脚本先 `import torch`、再 `import stereo_sdk`，需要在导入 torch 前手动 `set TORCHDYNAMO_DISABLE=1`。

### 报 `ModuleNotFoundError: No module named 'omegaconf'`

**原因**：FFS 的权重文件里内嵌了 OmegaConf 的 `DictConfig`，`torch.load` 反序列化时需要它；但 FFS 源码里并不 `import omegaconf`，所以 pip 依赖分析抓不到。

**处理**：`python -m pip install omegaconf`（`requirements.txt` 已列出）。

## 2. Python 环境相关

### `import torch` 失败 / 换了个终端就找不到包

**原因**：机器上有多份 Python。系统 PATH 里的 `python` 可能来自 IDE 或应用自带运行时，不是你以为的那一份。

**确认**：

```bat
where python
python -c "import sys; print(sys.executable)"
```

**处理**：后续命令写全路径，例如

```bat
"C:\Users\<你>\AppData\Local\Python\pythoncore-3.14-64\python.exe" main.py
```

`tools/` 下的启动器中，`启动_普通权限.bat`、`启动_管理员.bat`、`标定采集_新板7x9_26mm.bat`、`相机OpenCV自检.bat`、`相机状态检查.bat` 都复用 `tools\find_python.bat` 的探测逻辑，改探测顺序只需改这一个文件。例外是 `tools\calib_gui.bat`：它有自己的一套三级探测，顶部还留着一条特定机器的 `PY=` 硬编码路径，探测不对时直接改那一行。

### `ModuleNotFoundError: camera`（用 SDK 时）

**原因**：只把 `stereo_sdk/` 目录拷到了别的项目里。`Session` 依赖仓库根目录的 `camera` / `pipeline_threaded` / `calibration` 等模块。

**处理**：在仓库根目录执行 `python -m pip install -e .`，不要手拷目录。

## 3. 相机相关

### 打不开相机，报 `E_ACCESSDENIED`（0x80070005）

**背景**：本项目早期曾判定“必须管理员权限”，该结论**已被推翻**。2026-10-21 复核结论：普通用户权限（Medium 完整性）完全够用。

**真实原因**：解释器进程或 `python.exe` 文件的**完整性标签被降为 Low**（继承自低完整性工作区/沙箱），Low 进程访问物理相机时在 DirectShow `BindToObject` 阶段被拒。

**确认**：

```powershell
icacls "<你的解释器路径>" | findstr /I "Mandatory"
```

若显示 `Mandatory Label\Low Mandatory Level`：

```powershell
icacls "<你的解释器路径>" /setintegritylevel Medium
```

然后重开终端。重装 Python 或更换工作区后标签可能再次变 Low。

**注意**：不要长期以管理员身份运行程序，那只是绕过，不是修复。

### 画面能打开但全黑

常见于选中了**虚拟摄像头**（如 `OMEN Cam & Voice`、`HP True Vision` 之类的软件摄像头）。这类设备的 `isOpened()` 与 `read()` 都返回 True，但读到的是全黑帧，**不能作为验收依据**。

**处理**：用 `python main.py --list` 或 `tools\相机OpenCV自检.bat` 确认索引，把 `config.yaml` 里的设备索引改到真实的双目相机。

### 两个后端都不行 / 某些索引打不开

本机实测：**MSMF 按索引打不开**，DirectShow 正常。`camera.py` 已实现 `DSHOW → MSMF → ANY` 回退，若仍失败，用诊断脚本逐配置探测：

```bat
python tools\probe_camera_backends.py
python tools\dshow_capture_test.py --index 1
```

### 提示相机被占用

同一时间只能有一个进程持有相机。常见占用者：浏览器视频页、会议软件、另一个本程序窗口。

锁文件是 `output\.camera.lock`（内容为 PID）。若上一个进程已退出而锁残留，程序会在下次启动时自动接管；若进程仍在，任务管理器结束它。

## 4. 点云与 3D 窗口

### `--mode pointcloud` 直接报错退出 / 3D 窗口打不开

**原因**：`import open3d` 在顶层会加载 `open3d.visualization.draw_plotly`，因此**必须同时装 `plotly` 与 `dash`**。缺哪个就报哪个。

```bat
python -c "import open3d, plotly, dash; print(open3d.__version__)"
```

**处理**：`python -m pip install plotly dash`。Python 3.14 上 open3d 只有 0.20.0 提供 cp314 轮子。

### 点云上下颠倒

**不是 bug**。数据按相机光学系存储（x 右、**y 下**、z 前），Open3D / MeshLab 把 +y 当“上”，所以查看时上下颠倒。3D 窗口内部只在显示时翻转 y；保存的 PLY 未翻转。

## 5. 数值不对

### 深度全是 0

按顺序看：`r.summary()` 的 valid 数（弱纹理、反光、超量程都会让有效点为 0）、`zmax` 是否设得太小、镜头保护膜是否未撕、目标是否在量程内（0.15~3.0 m）。

### 深度数值明显偏大或偏小

**最常见原因**：分辨率与标定不匹配。标定按 1280×480 完成，改了采集分辨率却没有重标定，`fx` 与主点就全错了。

其次检查 `config.yaml` 的 `depth.calibrated` 是否为 `true`；为 `false` 时用的是厂家标称基线 60 mm（实测为 64.891 mm），误差约 8%，且**禁止用于测量**。

### 标定后效果反而更差

换板型重标过的一次实测结果明显更差（单眼 RMS 0.272 px、双目 0.379 px、极线失准 12.8 px），说明**板型与工作距离必须匹配**。当前生效的标定用 DFOPTIX Q12-50-3 玻璃板，工作距离 9~17 cm。详见 [阶段5_标定实测记录.md](阶段5_标定实测记录.md)。

## 6. 保存与路径

### 保存的 PNG 是空的 / 文件不存在

**历史问题，已修**：中文路径下 `cv2.imwrite` 会静默失败。项目已统一走 `depth_utils.imwrite_image`（内部用 `cv2.imencode` + 字节写入）。若你绕过它自己调 `cv2.imwrite`，在中文路径下仍会遇到。

### 有权保存不了文件

EXE 放在 `C:\Program Files` 之类需要提权才可写的目录时，`output\` 与 `logs\` 写入会失败。**把整个文件夹移到用户目录**（如 `D:\Tools\StereoCamera\`）。

## 7. 网络与下载

本机实测的下载通道可用性：

| 通道 | 结果 | 说明 |
|---|---|---|
| PowerShell / .NET `Invoke-WebRequest` | 失败 | `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS` |
| `git clone` / `git ls-remote` | 失败 | git for Windows 默认用 schannel，原因同上 |
| **Python `urllib` / `pip`** | **正常** | 用 OpenSSL，GitHub raw / HuggingFace / Google Drive 均可 |

因此本项目的下载动作统一走 Python：权重用 `tools\fetch_ffs_weights.py`，装包用 `python -m pip`。若必须用 git，可临时切后端（只影响本次命令）：

```bat
git -c http.sslBackend=openssl clone <仓库地址>
```

### 权重下载失败或中断

脚本支持断点续传前的临时文件（`.part`），重跑即可。Google Drive 的大文件会插一层“确认下载”页面，脚本已按表单原样重建请求；若仍失败，可用浏览器手动下载，但**目录结构与文件名必须一致**：

```
weights/23-36-37/cfg.yaml
weights/23-36-37/model_best_bp2_serialize.pth
```

## 8. EXE 相关

### 双击没反应 / 一闪而过

看 `logs\app-日期.log`。若杀毒软件隔离了 exe，把整个文件夹加入信任后重新解压一份干净的。

### 提示缺少 `VCRUNTIME140.dll` 或 `MSVCP140.dll`

安装 Microsoft Visual C++ 2015–2022 Redistributable (x64)。这是唯一没有打进包里的系统级依赖（另有 NVIDIA 驱动）。

### 提示找不到权重或 config

exe 旁边必须有 `config.yaml`、`calibration\`、`weights\23-36-37\{model_best_bp2_serialize.pth, cfg.yaml}`。**不要只拷 exe。**
